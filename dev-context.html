01 / GAME LOOP

单局推进

spawner.js 拥有关卡阶段状态；玩家/敌人规则各自更新，main.js 汇总每帧推进。击败最终区域首领后穿过传送门获胜；阵亡后进入结算并发放局外碎片。

01 / ENTER>

选英雄 · 开局

读取局外强化，创建玩家，从第一区域开始。

02 / SURVIVE>

敌潮 · 成长

清理数波敌人，收集装备与金币；升级选择天赋并升级技能。

03 / DEFEAT>

首领 · 传送门

闪避预警技能、击败区域首领，开启前往营地的通路。

04 / PREPARE

营地 · 下一关

恢复状态、购置装备并进入下一区域；最终获胜或阵亡结算。

03 / CHANGE ROUTES

从哪里开始改

新增英雄：复制 hero_*.js 配置模式、实现技能/被动钩子，再在 index.html 注册脚本并加入 HEROES。

新增物品/天赋/敌人：分别改 data_items.js、data_talents.js、data_enemies.js；加敌人 key 到 STAGES[].pool 才会出现在相应区域。

修改伤害：以 combat.js 的 dealDamage() 为集中入口，注意护甲/魔抗、护盾、被动、暴击与击杀钩子顺序。

  • 英雄技能 / 三个 hero 模块
  • 掉落规则 / data_items
  • 升级选择 / data_talents
  • 关卡内容 / data_enemies
  • 路径/碰撞 / map.js
  • 界面行为 / hud.js / ui.js

04 / LOCALES

i18n 接入方式

显示边界统一翻译

screen() 通过临时 DOM 翻译菜单文本和 data-tip；HUD 的 setText() / setHTML()、tooltip、banner 与 Canvas 飘字各自通过 I18N 显示。带数字的动态短句使用规则匹配，战斗和存档数据维持原有英文键和数值。

保存独立、切换可往返

语言记在 pixelLeague.locale.v1，与 pixelLeague.meta.v1 的局外成长分开。菜单保留原始模板以便切回英文；HUD 作缓存失效后重绘。新增玩家可读文案时同步补词典和动态格式规则。

// Localize display text without changing gameplay data
 element.textContent = I18N.t(sourceText);
 element.innerHTML = I18N.html(sourceMarkup);

05 / RUNBOOK

运行与验证

直接用浏览器打开 index.html，项目没有包安装、构建或服务器前置条件。局内地图随机生成；验证需要实际操作游玩路径，而非比对固定地图截图。

语法检查

可运行 node --check js/i18n.js，也可对修改的经典脚本逐个使用同一命令。当前仓库没有自动化测试、lint 或构建脚本。

关键手测路径

刷新后确认语言偏好；中英来回切换；打开英雄技能提示；进入游戏检查阶段 HUD、等级/天赋、拾取物品、营地、暂停与结算。确认局外强化仍保持原值。
