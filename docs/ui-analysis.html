MODULE ANALYSIS / js/ui.js

界面状态与
动作路由

ui.js 管全屏 DOM 页面和流程动作，不负责逐帧 HUD 绘制。它把当前页面保存在 UI 中，以 data-act 把用户输入路由到 UI_ACT，并通过 G.state 控制游戏模拟是否推进。

UI临时页面/商店状态对象
screen()模板注入 + 绑定动作/tooltip
UI_ACT声明式动作名到 handler
uiKey()非 play 状态快捷键入口

01 / MODULE CONTRACT

UI 对象保存什么

cards / onCardsDone

当前候选卡与选卡完成后的可选回调。

shop / rerollCost

营地商品数组、递增刷新价格和 wisdom 购买标记。

ended

结算幂等保护，避免同一局重复发放结算/碎片。

html / screenClass

最近一次屏幕模板和 class；语言切换时重建可见屏幕。

HUD、tooltip、技能栏不属于这个 UI 状态对象：HUD 更新在 hud.js，DOM 外壳定义于 index.html，样式主要在 css/style.css。

02 / TEMPLATE & EVENT ROUTING

screen() 的渲染/交互契约

screen(html, cls)↓记录 UI.html / UI.screenClass；设置 #screen class。
I18N.html(html) → innerHTML↓按当前语言翻译页面模板，再替换 DOM 内容。
[data-act] → UI_ACT[name]↓点击时传 data-arg 和 button；handler 执行业务流程。
[data-tip] → bindTip()↓复用 HUD tooltip 机制；页面关闭时清除内容并隐藏提示。

每次重新渲染都会替换 #screen 子树并重绑事件。动作名与动作实现分离：模板可读出交互意图，具体逻辑集中在 UI_ACT。按钮 helper btn() 只生成带 data-act/data-arg 的标记，不独自执行行为。

03 / STATE GRAPH

界面状态如何影响模拟

title

标题与菜单；主循环可显示漂移背景。

select

挑选 HEROES；选择后 startRun。

play

stepPlay 更新战斗、刷怪、相机与 HUD。

cards

升级选择期间不调用 stepPlay；选完返回 play。

pause

暂停覆盖页；Esc 恢复，放弃则结算。

camp

营地商店；购买/出售/休整后开始下一关。

armory

局外永久强化；读写 meta localStorage。

over

胜负结算、碎片奖励、重开/返回标题。

frame() 仅在 G.state === 'play' 时调用 stepPlay(dt)；title/select/armory 推进背景动画；cards/pause/camp/over 不推进战斗世界，但若有地图仍会绘制静止世界画面。

05 / IMPORTANT FLOWS

两条有回调的 UI 流程

升级卡流程

main.stepPlay() 发现 pendingCards → openCards() 切到 cards → 玩家选卡 → applyCard() 改 Player → 减少待选数 → 还有待选就再生成卡 → 最后关闭屏幕回 play。

智慧购买流程

营地点击 wisdom → 扣金币、置 UI.wisdom、防止重复购买、pendingCards +1 → openCards(renderCamp) → 选卡完执行回调重新画营地，不直接返回 play。

商店购买

校验库存、商品和金币 → gold 扣款 → item 放入 Player.items → shop slot 置空 → recalc() 并设置 HUD dirty → 重画 camp。

关卡过门

该模块不决定首领何时死亡；spawner 进入 clear 后玩家触门会调 openCamp() 或第五关 endRun(true)。UI 负责营地的购买与继续。

06 / KEYBOARD ROUTING

键盘事件的分流边界

事件来源状态/按键结果
core.js → G.onKeyDownG.state 为 playmain.js 接收移动、攻击、施法、暂停等局内输入。
core.js → G.onKeyDown其他状态main 将事件交给 uiKey(e)。

07 / LOCALIZATION & PERSISTENCE

页面模板与长期数据分开

本模块触及的存档

页面读取 meta 状态，军械库购买调用 buyMeta()，结算调用 awardShards()；实际读写规则在 meta.js。UI.html 只缓存当前模板，不是档案。

语言切换时恢复 UI

ui.js 注册 I18N.setOnChange()：若 screen 可见，用缓存的原始 HTML/class 再调用 screen()；HUD/banner 则交还 hud 更新函数。

模板和数据职责

screen() 对传入字符串执行 I18N.html()；玩家/装备数值仍存于对象，不通过翻译后的 DOM 反读。

动态内容来源

卡片、技能、物品提示和英雄描述来自数据模块；页面生成器将展示内容拼进模板，按钮动作再通过稳定 action key 连接行为。

08 / COUPLING & MAINTENANCE

修改 UI 时注意的约束

约束原因/后果
UI_ACT 键要与模板 data-act 一致screen 运行时按字符串查表并直接调用；拼错动作名没有降级分支。
每次 screen() 都替换子 DOM直接挂在旧节点上的监听会丢；交互应在模板创建后绑定，或使用委托。
G.state 同步决定模拟是否前进新增弹窗状态需确认 pause、键盘路由、pendingCards、主循环分支行为。
endRun() 有 ended 防重入阵亡延迟回调与按钮可能交错；清算奖励不可重复写入。
UI 与 HUD 分层screen 管整屏菜单；hud 管游戏内持续数据显示。不要在 UI 屏幕生成逻辑里复制 HUD 更新。
数据属性插入 HTML当前业务数据多为内置定义；如接入外部/玩家输入，需要对文本和属性值做 HTML escaping。
