01 / ENTITY MODEL

继承树与职责边界

实体使用原生 class 继承，公共战斗/动画状态集中在 Unit；玩家和敌人各自扩展行为，首领只在敌人之上增加首领专属状态与技能编排。

Unitjs/entity.js
  • 位置、碰撞半径、生命、基础属性袋
  • 控制状态、护盾、持续伤害、击退
  • 朝向、移动/攻击动画与共用状态更新
extends Unitextends Unitextends Enemy
Playerjs/player.js
  • 英雄配置、等级/经验、技能等级与冷却
  • 属性重算、移动/攻击指令、施法
  • 装备、增益、天赋、额外技能与路径
Enemyjs/enemy.js
  • ENEMY_DEF 配置、AI 类型、关卡缩放
  • 追击/攻击/冲锋、死亡奖励与掉落
  • 精英属性通过 elite 标志调整
Bossjs/boss.js
  • 继承 Enemy 的基础 AI 与死亡流程
  • 首领技能预警/施放轮换、狂暴阶段
  • 击杀后通知关卡流程创建传送门

注意：图中第三条继承线表示 Boss extends Enemy，不是 Boss extends Unit。Boss 构造器先调用 Enemy 构造器，再覆盖首领属性和奖励。

02 / UNIT SHAPE

Unit 对象字段分区

空间与生命

x, y, r, z
hp, st, alive

世界坐标、碰撞半径、高度、当前生命和属性字典。构造初始 hp=1；子类构造器随后设置真实值。

控制与防御

stun, slowT, slowAmt
blind, silence, root
shield, shieldT, invuln, flash

控制效果使用秒数倒计时；护盾独立吸收伤害，invuln 阻断伤害。

持续效果与位移

dots[], knock, lastHurt

DOT 记录源、DPS、剩余时长、伤害类型和 tick；击退记录速度与剩余时间。

朝向与动作

face, animT, moving
atkAnim, atkCd, windup

animFrame() 从攻击/移动状态派生精灵帧，不独立保存帧编号。

成员作用
speed由 st.ms、减速比例及 root 状态计算。
disabled仅由 stun > 0 判断。
slow / stunFor应用控制并乘以可选的 ccRes 抗性。
addShield / dot添加护盾或可按 tag 刷新/合并的持续伤害。
knockTo把目标位移换算为速度，交给 tick 更新。
tickStatus(dt)衰减控制/防御计时，应用击退并触发 DOT 的 dealDamage()。
faceTo / animFrame更新水平朝向，按攻击优先、移动其次选择动画帧。

血条绘制函数也放在 entity.js：drawHpBar() 区分玩家/精英与普通敌人；精英/玩家显示等级框、延迟血量尾迹及护盾段。

03 / COMPOSITION

运行时对象如何组合

G : GlobalState

游戏唯一共享状态容器。拥有当前 player、enemies、地图、镜头，以及投射物、掉落、区域、计时器和特效数组。

Player → hero

引用 HEROES 中的配置对象。属性成长、技能 Q/W/E/R、被动、角色专属卡片和生命周期钩子都由该配置驱动。

Player → items[]

物品为数据对象，含 uid/name/rarity/stats，可选 passive/desc。recalc() 聚合属性。

Player → extras

extras 保存技能等级，extraState 保存每项运行状态；技能行为和绘制由 EXTRAS 定义。

G.enemies[]

同时容纳 Enemy 与 Boss。主循环按 alive 更新/绘制，击杀后由 spawner 处理首领完成事件。

G.map : MapData

biome/tile/block/props/flow/tiles。地图模块另提供移动碰撞、A* 玩家寻路和 BFS 敌人流场。

G.projs[]

普通对象而非 class：追踪弹以 homing/tgt/spd 表示；直线弹以 vx/vy/r/hit/pierce 表示，行为由回调承载。

G.drops[]

以 kind 区分 gold、potion、item；还可带位置、高度/抛掷速度和拾取锁定。

G.fx / parts / texts

分别保存绘制效果、粒子和浮字记录；创建者负责提交，updateFx() 衰减，render/fx 负责显示。

临时对象字段/变体生命周期
G.runstage/wave/phase/queue/gold/kills/time/portal/boss 等startRun 建立；startStage/startWave/spawnBoss 推進；结算由 UI/meta 完成。
技能区域 G.zones[]x/y/r/t/tick 与可选颜色等stepPlay() 衰减 t 并回调 tick，到期移除。
定时任务 G.timers[]{t, fn}later() 入列；到期由 tickTimers() 调用闭包。
局外存档shards/up/runs/wins/best/bestTimemeta.js 通过 localStorage 的 pixelLeague.meta.v1 持久化。

04 / RENDER

呈现世界

render.js 深度排序绘制 Canvas；HUD 和菜单绘制在 DOM。

playerAttack / skillshot / dot↓普攻、技能、持续伤害等入口
dealDamage(src, target, amount, type, options)↓统一进行抗性、增减伤、护盾和生命扣减
onPlayerDealt / onPlayerHurt / killUnit↓触发吸血、装备/英雄钩子、复活或死亡
Enemy.onDeath → drops → Player.pickups↓奖励进入 run 或玩家背包，并请求 HUD 更新

游玩帧的控制入口是 frame() / stepPlay()；玩家细节在 Player.prototype.update()，敌人 AI 在 Enemy.update()。伤害统一从 dealDamage() 进入。

06 / CONTENT MODEL

数据配置如何成为可玩对象

多数可扩展内容先以普通对象登记，再由通用系统创建运行时对象；英雄特例通过回调组合，而不是为每位英雄派生一套 Player 类。

HERO_* → HEROES

五个英雄脚本导出配置，hero_aldric.js 汇总列表；选择界面把选中配置交给 startRun(hero)。

hero config → Player

new Player(hero) 保存配置引用。recalc() 汇总基础成长、装备、天赋、局外强化和增益，技能/被动通过配置钩子执行。

ENEMY_DEF → Enemy

阶段敌人池生成 key，Enemy 读取属性、精灵和 AI 类型，按 stage/wave 缩放后放进 G.enemies。

BOSS_DEF → Boss

每阶段指定一个 Boss key。Boss 复用 Enemy 的移动/普通攻击框架，另读取技能轮换、召唤小怪 key。

BASE_ITEMS / LEGENDARIES

rollItem() 按来源权重生成随机属性物件；掉落被拾取后进入背包，属性改变时重算 Player stats。

TALENTS + EXTRAS

genCards() 混合通用天赋、英雄专属卡和额外技能；applyCard() 写回属性、flag 或技能等级/state。

配置作战定位关键定制点主要扩展钩子
HERO_KESTREL远程射手Vulnerable 标记、命中消耗、E 位移tick / onAttack / onKill
HERO_VELA近战决斗家Vital 真伤/治疗、格挡、挑战目标tick / dmgTaken / canAct / onDealt
HERO_FORTUNE远程枪手每目标周期强化普攻、弹射、持续区域、扇形弹幕onAttack / onKill
HERO_CAITLYN远程狙击手穿透衰减、陷阱区域、后坐位移、周期爆头tick / onAttack / onKill
HERO_ALDRIC近战重装无消耗、击杀成长、防御姿态、旋转攻势与真实伤害处决statMod / tick / canAttack / dmgTaken / onAttack / onKill

扩展约定：英雄的 skills[k] 含冷却、消耗、瞄准方式、说明生成器和 cast(p, tx, ty, rank)；通用 Player.cast() 负责合法性、消耗和冷却。新角色行为应尽量挂在英雄钩子，避免把角色 ID 判断散落进 combat.js。

BREAK›

休整

倒计时结束后开始一波；开局及过波间均使用休整阶段。

WAVE›

敌潮

队列按间隔批量生成，含精英；波次结束后清理剩余敌人。

BOSS → CLEAR›

首领与传送门

最后一波清空后生成首领；击败首领转为 clear 并放出传送门。

CAMP / WIN

营地或胜利

前四关进入商店并开下一关；第五关通过传送门结束本局。

地图生成对象

44×44 地图包含 tile/block 的 Uint8Array、flow 的 Int16Array、物件列表及预制 tiles。生成道路、边界和障碍群，并从中心做可达性遍历，把不可达空格封起来。

空间算法分工

玩家移动使用 8 向 A*，有视线时直接走单段，路径结果再做 string-pull 平滑；敌人共用以玩家为源的 BFS 距离场选方向。moveUnit() 分轴移动，并用半径外接方形的四角采样阻挡格。

生物群系与外观

BIOMES 提供草地、道路、花色、树叶、屋顶、边界和障碍类型。buildTiles()/buildProps() 以小 Canvas 程序化绘制，进入阶段后将整张地面预渲染。

画面深度与坐标

core.js 用等距投影转换世界坐标；renderWorld() 把物件、单位、掉落、弹道按 x + y 排序，先画低分辨率 buffer 再 nearest-neighbor 放大。HUD/浮字使用全分辨率 Canvas 或 DOM。

层次划分：碰撞、寻路属于模拟层；sprite/props 只提供图像生成；render 只读取对象状态作显示排序。地图随机生成，因此静态截图不能当作关卡数据本身。

08 / APPLICATION FLOW

游戏界面状态与输入边界

G.state 是主状态开关。UI 通过 screen() 渲染 DOM 并把 data-act 映射到 UI_ACT；游戏画布循环只在 play 推进战斗，菜单背景状态单独更新。

title

主菜单；Canvas 显示漂移背景。进入选人、军械库或帮助。

select / armory

选择英雄开始一局，或读写局外升级。两者仍显示菜单背景。

play

唯一运行完整战斗模拟的状态；键鼠输入路由到 Player 指令/技能。

cards

暂停局内时间等待选天赋；允许数字键选择、T 重抽和升级技能。

pause / camp

暂停或商店 DOM；营地购买、出售、恢复后再开启下一关。

over

展示胜负统计，计算碎片并保存局外结果；可重新开局或进军械库。

10 / MAINTENANCE NOTES

从当前实现可见的约束

字段不是封闭 schema

Unit 建立公共字段，但英雄钩子和 Boss/Enemy 会动态添加状态；Player.st 也是运行时重算的普通对象。加字段时要检查写入、每帧更新、清理和渲染的完整生命周期。

Player 更新分散在两个文件

player.js 先声明 class，player_update.js 再补充 Player.prototype.update/itemTick/pickups。这是脚本加载顺序的一部分。

表示层与规则层共用引用

渲染器直接读取实体字段和全局集合，HUD 也读取 Player 的等级、技能、装备和阶段状态。改名或变更对象形状时需同步调用方。

菜单背景使用占位玩家

initBackdrop() 临时赋给 G.player 一个普通对象，不是 Unit 或 Player；后台状态下不可假定所有实体字段/方法都存在。

开发导览存在内容漂移

dev-context.html 仍写 26 个脚本，且模块表只列 Kestrel/Vela/Aldric；dev-context.md 也未列 Fortune、Caitlyn 与 sound.js。当前入口实际加载 29 个游戏脚本，HEROES 汇总 5 位英雄；图标页另载 icon-gallery.js。

验证目前以手动为主

仓库没有自动化测试/构建配置。可对改动脚本执行 node --check js/<file>.js，再实际验证开局、升级、战斗、拾取、关卡转场和结算。
